# LightNMEA - пример ESP32-C3 + MAX7219 (8-знаковый 7-сегментный индикатор)

Демонстрация LightNMEA на плате **LuatOS CORE-ESP32-C3** с семисегментным
индикатором на **MAX7219** (8 знакомест, через преобразователь уровней 5 В).

Прошивка читает NMEA с GNSS-модуля (38400, 8N1) и каждые 3 секунды
переключает страницы на индикаторе:
1) время `HH-MM-SS` (UTC);
2) широта в десятичных градусах (например `12.34567`);
3) долгота в десятичных градусах (например `45.67890`).
Пока нет валидного фикса - на индикаторе `--------`.

## Подключение

| Сигнал | GPIO |
|--------|------|
| SPI SCK  | GPIO4 |
| SPI MOSI (DIN) | GPIO6 |
| SPI MISO | GPIO5 (не используется) |
| CS (активный LOW) | GPIO7 |

GNSS-модуль (UART1, 38400 8N1):

| Сигнал модуля | Пин платы |
|---------------|-----------|
| TX (синий) | GPIO3 (UART1 RX) |
| RX (зелёный) | GPIO2 (UART1 TX, можно не подключать) |
| VCC (красный) | 3V3 |
| GND (чёрный) | GND |

[!] **UART0 (GPIO20/21) для GNSS не использовать** - на этой плате он занят
USB-мостом CH343 (лог в `/dev/ttyACM0`), GNSS на UART0 ломает USB-обмен.
Провода идут перекрёстно: TX модуля -> RX платы, RX модуля -> TX платы.

[!] **GPIO2 - strapping-пин**: при старте должен быть высоким. RX модуля -
вход и его не тянет, но не ставьте на GPIO2 подтяжку к земле. Если TX
модулю не нужен (только приём NMEA) - GPIO2 можно вообще не подключать.

[!] **GPIO11..17 заняты внешней флэш-памятью - не подключать к ним ничего!**

## [!] ВАЖНО: параметры внешней флэш-памяти

**Это причина N1 "неработающих" прошивок на этой плате** (и вообще на платах
с внешней SPI-flash: ESP32-C3, ESP32-S3 и др.).

У платы **нет встроенной flash** - чип ESP32-C3 работает с **внешней
микросхемой SPI-flash 4 МБ**. Код загружается только из неё, и загрузчик
стартует лишь тогда, когда параметры шины в заголовке прошивки (flash-режим,
частота, размер) **совпадают с реальным железом**. Дефолтный профиль
`esp32-c3-devkitm-1` в PlatformIO рассчитан на другую разводку - с ним плата
выглядит **полностью мёртвой**: ни логов в мониторе порта, ни реакции на
reset, при полностью исправном железе.

**Поэтому в [`platformio.ini`](platformio.ini) уже прописаны правильные
параметры - не удаляйте и не меняйте их:**

```ini
board_build.flash_mode = dio      ; НЕ qio - у платы DIO-разводка шины
board_build.flash_freq = 40m      ; консервативная частота шины
board_build.flash_size = 4MB
```

### Если плата уже "ослепла" (была прошита с неверными параметрами)

1. Верните три строки выше в `[env:esp32c3]`.
2. Полностью сотрите флэш (обязательно - частичная перезапись оставит
   несовместимый заголовок):

   ```sh
   python3 ~/.platformio/packages/tool-esptoolpy/esptool.py \
       --port /dev/ttyACM0 --chip esp32c3 erase_flash
   ```

3. Залейте образ заново: `pio run -t upload -e esp32c3`.

### Полезно знать про эту плату

- ROM-загрузчик платы **молчит на UART** при обычной загрузке (eFuse
  `UART_PRINT_CONTROL = Disable`) - отсутствие стартового баннера в мониторе
  порта **не** признак поломки.
- Кнопка **BOOT = GPIO9**: случайные нажатия отправляют чип в download mode
  ("waiting for download" в логе). Для обычной перезагрузки используйте
  только **RST (EN)**.
- USB-мост **CH343**: при чтении логов pyserial'ом выставляйте
  `ser.dtr = False; ser.rts = False` после `open()`.

## Сборка и запуск

```sh
pio run -e esp32c3            # сборка
pio run -t upload -e esp32c3  # прошивка
pio device monitor -b 115200  # монитор
```

После включения индикатор показывает `88888888` (проверка всех сегментов),
затем `--------` до первого валидного фикса. Дальше страницы чередуются
каждые 3 секунды: время -> широта -> долгота.

Параметры в [`src/main.cpp`](src/main.cpp):
- `PIN_GNSS_RX = 3`, `PIN_GNSS_TX = 2` - пины UART1;
- `PAGE_MS = 3000` - период смены страницы.

Время на первой странице выводится в **UTC**, без смещения часового пояса.

В USB-лог раз в секунду печатается
`page=.. valid=.. sats=.. utc=.. lat=.. lon=..`.
