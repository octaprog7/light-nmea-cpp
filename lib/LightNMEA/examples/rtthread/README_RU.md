# LightNMEA + RT-Thread

Пример интеграции библиотеки LightNMEA с RTOS [RT-Thread](https://www.rt-thread.io/).
Приложение читает поток данных NMEA из UART-девайса (`rt_device` + колбэк
`rx_indicate` + семафор), копит байты в кольцевом буфере и парсит их в главном
потоке библиотекой LightNMEA (`NMEAStreamReader` + `Parser`).

Ядро LightNMEA (`light_nmea.hpp`, `nmea_stream_reader.hpp`, `nmea_formatter.hpp`)
не зависит от Arduino/POSIX, поэтому работает в RT-Thread без изменений.

## Два режима

| Режим | Источник данных | Включение |
|-------|-----------------|-----------|
| UART (по умолчанию) | реальный GPS-модуль на serial-девайсе | — |
| Симуляция | встроенные предложения NMEA из потока-производителя | `LIGHTNMEA_SIM_FEED=y` |

Режим симуляции удобен для плат без подключённого GPS (например,
`qemu-vexpress-a9`) и для CI-тестов.

## Требования

- BSP RT-Thread 4.x с:
  - поддержкой C++17 (`RT_USING_CPLUSPLUS`, `gnu++17` в `CXXFLAGS`);
  - драйвером serial (`RT_USING_SERIAL`, также работает `RT_USING_SERIAL_V2`)
    для режима UART.

## Сборка и запуск

### Реальная плата (например, BSP STM32)

1. Скопируйте этот каталог в дерево BSP (или смонтируйте как каталог
   `applications`), чтобы SCons подхватил `SConscript`.
2. Включите пример в `menuconfig` (`Kconfig` из этого каталога):
   - `LIGHTNMEA_UART_NAME` — имя serial-девайса, к которому подключён GPS
     (по умолчанию `uart1`).
3. Соберите и прошейте:

   ```console
   scons
   ```

4. Подключите GPS-модуль к выбранному UART (9600 бод у большинства модулей)
   и наблюдайте вывод в консоли RT-Thread (msh):

   ```
   LightNMEA RT-Thread example started (UART: uart1)
   Fix: Yes
   satellites: 8
   latitude: 48.117300
   longitude: 11.516667
   ...
   ```

### QEMU (qemu-vexpress-a9, без железа)

```console
# в каталоге BSP qemu-vexpress-a9 с добавленным примером:
menuconfig            # LightNMEA example -> включить LIGHTNMEA_SIM_FEED
scons
./qemu.sh
```

Встроенный поток-производитель отправляет примеры NMEA-предложений в
кольцевой буфер, распознанные координаты печатаются в консоль.

## Как это работает

1. `rt_device_find(LIGHTNMEA_UART_NAME)` + `rt_device_open(..., INT_RX)` —
   serial-девайс открывается в режиме прерываний на приём.
2. Колбэк `rx_indicate` (`uart_input`) только освобождает семафор `ln_rx` —
   никакого парсинга в контексте прерывания.
3. Главный поток просыпается по семафору и дозагружает буфер драйвера в
   кольцевой буфер (`uart_drain`).
4. `RingStream` реализует абстрактный `light_nmea::Stream::read()` поверх
   кольцевого буфера.
5. `reader.read_available(parser, stream, get_time_ms)` собирает NMEA-пакеты
   и передаёт их парсеру (`rt_tick_get_millisecond()` даёт метки времени для
   анти-спам фильтра).
6. Результат печатается через `rt_kprintf`.

## Примечания

- Кольцевой буфер (512 Б) сглаживает всплески между тиками планировщика;
  при переполнении байты молча теряются (GPS продолжает передавать,
  следующие предложения остаются валидными).
- В режиме симуляции поток-производитель (`ln_sim`) заполняет тот же
  кольцевой буфер, поэтому путь данных идентичен режиму UART.
- `main()` выполняется в стандартном главном потоке RT-Thread; в режиме UART
  дополнительные потоки не создаются.
